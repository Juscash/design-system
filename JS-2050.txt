### Descrição

O objetivo desta tarefa é **documentar os componentes do Design System que ainda não possuem documentação formal**, garantindo padronização, clareza de uso e fácil adoção pelos times de desenvolvimento. A documentação deve seguir o padrão já existente no Design System, utilizando o **Ant Design (antd)** como base e respeitando integralmente o visual definido pela equipe de UX.

**Componentes a serem documentados**

- Datepicker _(copiar do SIJ para a biblioteca)_
- Badge
- Alert
- Notification _(Sonner no design)_
- Slider
- Progress
- Collapse
- Popover
- Tabs
- Breadcrumb
- Navbar
- Sidebar
- Carousel
- Drawer
- Modal _(extensão do Alert – Alert Dialog no design)_
- Empty State

### Solução

Para cada componente, a documentação deve conter, no mínimo:

- Descrição do componente e seu propósito
- Quando usar e quando não usar
- Variações previstas no design
- Exemplos de uso
- Observações ou boas práticas (quando aplicável)

Toda a documentação deve ser centralizada no **Confluence**, com linguagem clara e acessível para desenvolvedores de diferentes níveis de conhecimento.

### Critérios de Aceite

1. Todos os componentes listados devem estar documentados no Confluence
2. A documentação deve estar alinhada ao Design System definido pela UX
3. O Datepicker deve ser reutilizado a partir do SIJ e documentado na biblioteca
4. A documentação deve permitir que qualquer desenvolvedor encontre e utilize os componentes sem dúvidas
5. **Validação final realizada em conjunto com a equipe de UX**
6. O progresso e os avanços desta história devem ser mantidos atualizados no card de acompanhamento.
